HeadLog – vom Code aufs Handy

Der komplette Kreislauf: Wie eine Änderung entsteht, wie GitHub daraus eine signierte App baut und wie sie ohne Play Store auf dem Handy landet – mit Updates, die die Daten behalten.

↓

↓

☁️ GitHub · tillraab/headlog

Ein Release Schritt für Schritt

So sieht ein typisches Update aus, z. B. „Erinnerung bei laufendem Kopfschmerz“.

  1. Wunsch formulieren du
    „Während Kopfschmerzen alle 3 h nachfragen, ob sie noch da sind.“
  2. Umsetzen & testen Agent
    Code, Unit-Tests, Test im Emulator mit vorgestellter Uhr.
  3. CHANGELOG + Version Agent
    Neuer Abschnitt ## [0.4.0], package.json auf 0.4.0.
  4. Commit, Tag, Push Agent
    Ab hier läuft alles automatisch.
  5. Bauen & signieren GitHub · ~3 min
    Release mit APK erscheint unter „Releases“.
  6. Update auf dem Handy Obtainium
    Innerhalb weniger Stunden automatisch – oder sofort per Pull-to-Refresh.

Die Befehle dazu

# prüfen
bun run check
bun run test

# Version festlegen: CHANGELOG.md + package.json anpassen
git add -A
git commit -m "Ask every few hours whether a headache is still there"

# veröffentlichen
git tag v0.4.0
git push origin main v0.4.0

Ohne Tag wird nur geprüft, nichts veröffentlicht. So kann man in Ruhe mehrere Änderungen sammeln und erst dann ein Release machen.

Versionsnummer
Muss mit jedem Release wachsen: 0.4.0 → 0.4.1 (Fix) · 0.5.0 (Feature) · 1.0.0 (großer Schritt). Android installiert keine „ältere“ Version über eine neuere.

🔑 Der Signaturschlüssel

Der einzige Teil, den du selbst sicher aufbewahren musst.

Wozu?

Jede APK wird digital unterschrieben. Android merkt sich bei der ersten Installation, wessen Unterschrift die App trägt, und installiert danach nur Updates mit derselben Unterschrift. So kann niemand eine gefälschte HeadLog-Version „drüberinstallieren“.

📁 Kopie 1: dein Rechner

~/projects/headlog-signing/

headlog-release.keystoreder Schlüssel
signing.envPasswort & Alias

Nicht im Repo. Nur dein Benutzer darf lesen.

☁️ Kopie 2: GitHub Secrets

Repo → Settings → Secrets → Actions

ANDROID_KEYSTORE_BASE64
ANDROID_KEYSTORE_PASSWORD
ANDROID_KEY_ALIAS / …_PASSWORD

Nur der Release-Workflow kann sie benutzen. Auslesen geht nicht – nur überschreiben.

✅ Deine Aufgabe

Den Ordner zusätzlich sicher ablegen, z. B.

  • als Anhang im Passwortmanager
  • auf einem verschlüsselten USB-Stick

Weil GitHub die Secrets nicht wieder herausgibt, ist das die einzige Kopie, die du wiederherstellen kannst.

Verloren? Solange die GitHub-Secrets bestehen, laufen Releases weiter. Fehlen beide, kann HeadLog nicht mehr aktualisiert werden: Backup machen → App deinstallieren (löscht die Daten) → neu installieren → Backup wiederherstellen.
Geleakt? Wer Schlüssel + Passwort hat, könnte ein „Update“ bauen, das dein Handy akzeptiert. Deshalb nie ins Repo, nie per Mail oder Chat.

📦 Wo deine Daten leben

Code und Daten sind komplett getrennt. GitHub kennt deine Kopfschmerzen nicht – außer du schaltest das Gist-Backup ein.

📱 Auf dem Handy

Alle Einträge in einer Datenbank im privaten App-Speicher (IndexedDB). Wird bei jedem Tippen sofort gespeichert. Updates behalten sie.

Deinstallieren oder „Speicher löschen“ = Daten weg.

💾 JSON-Backup

Einstellungen → Daten → „Backup exportieren“. Eine Datei, die du z. B. in Drive oder per Mail sicherst. „Backup wiederherstellen“ liest sie wieder ein.

☁️ Gist-Backup (optional)

Mit einem GitHub-Token: automatische Sicherung in einem geheimen Gist, sobald du die App verlässt. Auf einem neuen Handy: Token eintragen → wiederherstellen.

Geheim = nicht auffindbar, aber nicht verschlüsselt.

Begriffe

BegriffWas es ist
Repository (Repo)Der Code mit kompletter Versionsgeschichte, auf GitHub unter tillraab/headlog, lokal in ~/projects/headlog.
Commit / PushEine gespeicherte Änderung / das Hochladen dieser Änderung zu GitHub.
TagEin Etikett auf einem Commit, z. B. v0.4.0. Startet den Release-Workflow.
GitHub Actions / WorkflowAutomatische Abläufe auf GitHub-Servern: CI (prüfen) und Android Release (bauen, signieren, veröffentlichen).
SvelteKitDas Web-Framework, in dem die Oberfläche geschrieben ist.
CapacitorVerpackt die Web-App in eine echte Android-App und gibt ihr Zugriff auf Benachrichtigungen, Vibration, Teilen-Dialog.
APKDie Installationsdatei einer Android-App.
ReleaseEine veröffentlichte Version auf GitHub, mit APK und Release Notes.
ObtainiumApp auf dem Handy, die GitHub-Releases beobachtet und Updates installiert – ein Play-Store-Ersatz für eigene Apps.
CLAUDE.mdAnleitung im Repo für Entwickler und KI-Agenten: Aufbau, Regeln, Stolperfallen, Release-Ablauf.
